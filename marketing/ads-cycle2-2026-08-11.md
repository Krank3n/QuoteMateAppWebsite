# Meta ads — cycle 2 decisions (2026-08-11)

Read `marketing/ads-log.md` (Phase-1 full-run entry) first — this doc is only
what changes and why. Authority for rules stays `fb-ads-growth-system-2026-07.md`;
§A below is a correction *to* that doc.

**One-line read of Phase 1:** $317.71 bought 416 visits, 4 signups, 0 customers.
The creative test never happened (Meta spent 78% on one ad), and cold Meta traffic
converted 10× worse than organic on the *same page* — an intent gap, not a broken
page. Phase 1 came in at $105.90/trial against a validated forecast of $90+/trial
for this channel. **It performed as predicted, and the prediction was that this
channel doesn't pay at our trial→paid rate.**

## A. Two corrections to the growth system

These are plan defects the run exposed, not execution mistakes. Fold them into
`fb-ads-growth-system-2026-07.md` §4/§5.

**A1. "$500 cap, test ≤4 concepts" was never arithmetically possible.**
§5.2 requires ~3× target CPA (~$180 at A$60) of spend before a concept can be
judged. $500 ÷ $180 = **2.8 concept judgments — total**. Phase 1 launched five.
The correct rule: *concepts per phase = budget ÷ (3 × target CPA)*, rounded down.
At $500 that is two, and the fifth ad should never have been made yet.

**A2. "ONE broad ad set, all creatives" and "test 5 distinct concepts" are in
conflict at $25/day.** Consolidation is right for *delivery* and wrong for
*learning* — Meta picks a favourite in the first days and starves the rest, so
the batch returns one data point. Both goals cannot be had at this budget. The
rule should be explicit about which one Phase 1 is buying:

> At <$50/day, run **two concepts at a time** in the single ad set, and when the
> question is "which hook wins" rather than "how cheap can this get", use Meta's
> A/B test (split test) so budget is forced even, not allocated. Add a third
> concept only when one of the two has passed or failed its $180 judgment.

Nothing about the 78/22 split says qm-a1 beat the others — the three defunded
creatives bought **cheaper** traffic ($0.39–$0.46/session vs $0.77). They are
untested, not losers, and go back in the queue at their turn.

**A3 (state it, don't fix it): at $25/day Meta's optimizer is not a participant.**
SignupStart cost $19–25; learning needs ~50/week, i.e. ~$150/day. Phase 1 was
always going to sit Learning Limited. That is fine — but the plan should say
Phase 1 buys a *creative + landing read*, and stop implying the algorithm
contributes. Do not chase the learning phase by switching to a cheap
traffic-style event; that is the clicker trap §3 already rejected.

## B. The page is not broken — don't "fix" it

*(Rewritten 2026-08-11 after the organic comparison. The first draft of this
section said fix the page first; that was wrong and the evidence is in
`ads-log.md` finding 4.)*

On the identical page, same fortnight, **mobile only**: organic converts 25.3% of
sessions into a product click, paid converts 2.5%. Paid visitors stay *longer*
(278s vs 263s). The homepage works; it works on people who arrived already
wanting it. Nothing here justifies a redesign, and a redesign would not have
moved Phase 1.

What is still worth doing is narrow, and B1 is the only one with a measured
defect behind it:

**B1. Stop paid traffic leaking to the app stores.** The hero shows App Store and
Google Play badges directly under the primary CTA, and the header shows a
"Download App" button. 3 of 10 paid product clicks went to Google Play, whose
badge hardcodes `referrer=utm_source%3Dquotemateapp.au%26utm_medium%3Dwebsite` —
so a paid install is attribution-dead *and* pays an extra install step before
signup. `AttributionBridge` already parses `utm_medium` on landing; when it is
`paid`, hide the store badges and the header download button so exactly one door
is open. Playbook §5 already states the rule ("ad traffic goes to the website →
web app only") — the page just doesn't implement it.

**B2. Pin paid traffic to one hero variant.** Paid split 207/212 across A/B.
Paying to randomise the landing page while also testing creative means neither
test can be read, so pinning is right regardless of which variant wins.

*Which* variant is a coin flip on this data, and the first draft of this doc got
it wrong by quoting only the upstream metric. Full paid funnel:

| | variant A | variant B |
|---|---|---|
| `web_app_click` | 3 | 4 |
| `google_play_click` | 3 | 0 |
| **product clicks total** | **6** | **4** |
| `cta_click` (generic, non-`/app`) | 1 | 6 |
| `onboarding_completed` | 4 | 3 |

B wins only on generic `cta_click`, which is not a product click. On the two
metrics that matter A is level-or-ahead. **Pinned to `variant=a`** — it is ahead
on completions and it is a near-exact message match for qm-a1's hook ("Still
pricing jobs at 9pm?" → "Don't quote at night"), which is the standard tiebreak
when conversion data can't separate two pages. Done in the ad URLs alone
(`app/layout.tsx`'s assignment script honours a `variant` query param and lets it
override an existing cookie), so no deploy. Note this keeps the Play-badge leak
(B1) live: A is the variant that leaked all 3 Play clicks.

**B3. A bespoke cold-traffic page is a hypothesis, not a fix.** It may still be
worth building — but frame it honestly: the homepage is built to *close* warm
intent, and cold social traffic needs something that *creates* intent (one
narrative, one exit, no full product surface, possibly a soft capture short of
"make an account"). That is a different page for a different job, not a repair.
Note also that variant A's hero ("Don't quote at night") already matches qm-a1's
hook almost exactly, so message mismatch is *not* the culprit — which is evidence
against a quick landing-page win.

**B4. Don't expect any of B1–B3 to rescue the channel.** Closing the whole 10×
intent gap with page work is not a thing that happens. At $0.76/session, even a
heroic 2.5% → 6% would put trials near $45 — better, but still gated behind a 2.1%
trial→paid rate that makes any CAC unrecoverable. §C and the Phase-2 gate are the
real decisions.

**The Phase-2 gate has not moved:** trial→monetised is 2.1% against a ≥5% gate,
and paid traffic has produced 0 monetised users. There is no case for raising
spend regardless of how cycle 2 reads.

## D. Creative for the cycle after next (build now, launch when a slot opens)

Per §5.5 — one iteration of the winner, one net-new. Both obey the tone rules
(no "AI", gender-neutral, verified numbers only, no invented scarcity).

**D1 — `qm-a1-pos` (winner iteration, single variable = the hook).**
Identical creative (`ad-creative/qm-a1-kitchen-9pm.png`) and identical primary
text to qm-a1. Change *only* the headline, negative frame → positive frame, which
is the open question §4a rule 4 flagged and Phase 1 never answered:

- Control (qm-a1): `Still pricing jobs at 9pm?`
- Variant (qm-a1-pos): `Quote it on site. Be done before the ute leaves.`

**D2 — `qm-d1` (net-new: the demo video that still doesn't exist).**
The playbook has called this the expected top performer since v1 and it has never
been built — yet `public/assets/videos/intro.mp4` already exists and runs in the
homepage hero. Cut a 30–45s vertical ad from it (or re-record in the same style):
one job talked in, materials appearing priced, quote sent. Captions burned in,
silent-watchable, no music-video edit.

- Headline: `Watch a full quote get built on the way to the next job`
- Primary text: `No cuts, no tricks — one job, quoted start to finish. Talk it in, the materials come in priced, labour and margin on top, and it lands in the customer's inbox with your business name on it. Free 14-day trial — and it doesn't start until the first quote gets made.`

Video is the one format the account has never run. If the still images keep
returning ~1% landing conversion, the format is the variable left untested.
